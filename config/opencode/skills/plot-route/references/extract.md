# 术语与实体提取（自启发循环）

本流程用于提取术语、人物关系、剧情结构或系统整理工程实体。执行前先读取 `references/rule.md`，按其中的收录、身份、字段和覆盖判据判断对象与方案。

## 任务范围

- 用户未限定范围时，覆盖当前工程全文（数据库 + 全部地图事件 + 公共事件）。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 优先程序化批量探查（Grep、`RmmvReadContext dbCatalog`），仅在无法程序化探查时逐条语义分析。

## 自启发循环

- 从任务目标、已有材料、调查结果和覆盖缺口中提炼可用于后续探查的特征模式或具体线索，称之为 `种子`。
- 根据种子发现下一批需要调查的目标，再从调查与处理结果中提炼新的种子。
- 重复前述过程，直到任务目标完成且所有种子均已消耗，称之为 `自启发循环`。

## 种子账本

种子账本保存在 `AGENT_RPG_TMP_DIR/TASKNAME-seeds.json`（临时工作材料，不入工程、不入记忆）：

- 账本记录实时调查状态，必须每轮更新，禁止跨轮补写。
- 轮次从 `1` 开始，新增或需重新调查的种子设为 `consumed = false`。
- 完成取证、结果处理和后续种子提炼后，将目标种子设为 `consumed = true`；尚需补查或受阻的种子保持 `false`。
- 同轮处理多个种子、搜索或采样均计为一轮，`completedRounds` 在本轮完成时加 `1`。

```jsonc
{
  "completedRounds": 1,
  "seeds": {
    "1": [
      { "pattern": "检索姓名与称谓中的「ヴァレン」，结合 dbCatalog 与事件语境核验家族归属。", "consumed": false }
    ]
  }
}
```

## 循环执行

### 循环入口

从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集。RMMV 工程的内容区域：

1. **数据库**：`RmmvReadContext` action=`dbCatalog`（actors、classes、skills、items、weapons、armors、enemies、states、system terms）取名称、昵称、简介；需要完整记录时用 action=`dbEntry`。
2. **地图事件对白**：`action=mapIndex` 选图 → `action=mapData`（offset/limit 分页）读目标事件 → `action=eventContext` 取结构化上下文。显示文字指令 `101/401`、选项 `102`、滚动文字 `105/405` 是正文来源。
3. **公共事件与系统**：`CommonEvents.json`、`System.json` 用 Grep 按 ID 或名称定位（**禁止整读大文件**）；开关/变量候选用 action=`stateSlots`。
4. **插件与 note**：Grep 扫描 `js/plugins.js`、`js/plugins/*.js` 与数据库 `note` 字段中的可见文本与命名引用。

### 循环轮次

每个循环轮次必须以写入种子账本作为结束：

1. 读取账本中未消耗的 `种子`（首轮从循环入口开始）。
2. 按种子中的特征模式探查，形成审查结论，准备变更数据但暂不写入。
3. 回看探查与处理过程，提炼新的种子，更新 `completedRounds` 与已消耗状态。
4. 写入种子账本文件。

重复执行直到同时满足：任务目标全部完成；没有新种子且全部已消耗；`completedRounds >= 3`。

## 种子探查方向

无需局限于此，错误、正确案例和不同处理方式都可以提供线索：

- **发现候选**：从角色姓名栏、首次登场对白、数据库简介中提取可检索的线索，调查对象身份与收录资格。
  - 例：`dbCatalog actors` 发现角色名后，Grep 该名检索全部出现位置，核验身份与登场范围。
- **扩展同类**：从已确认对象中提取命名或使用特征，调查其他可能需要收录的同类对象。
  - 例：确认 `紅蓮の印` 是技能名后，Grep `の印`，结合获得、发动语境调查其他技能。
- **核验差异**：发现同名异指、一词多义或相似名称处理不同时，调查差异是否符合各自身份与语境。
  - 例：`ルナ` 在 A 图是人名、B 图是月亮意象，核验是否需要条件消歧。
- **追查关联**：确认新的身份、别名、所属或命名体系后，调查受该发现影响的其他对象与规则。
  - 例：确认 `エレン` 与 `ノア・ヴァレン` 是姐弟后，检索 `ヴァレン`，核验其他姓名与家族称谓的归属。
- **检查边界**：从新增命中、反例和覆盖缺口中提取线索，调查规则的适用条件。
  - 例：角色名 `セラ` 同时命中普通词 `セラミック` 后，核验局部语境能否区分。

## 取证方法

- **名称与字段证据**：`RmmvReadContext` action=`dbCatalog`（带 query 过滤）与 action=`dbEntry` 取数据库字段；Grep 对 `data/*.json`、插件 JS 做**连续字面命中**扫描，记录文件、地图 ID、事件 ID、数组位置。
- **语境证据**：action=`eventContext` 取指定事件的完整命令列表；同一事件页内相邻指令、同图相邻事件的对白构成剧情链，等价于"邻近语境"。跨图引用用 action=`commonEventReferences` 与 Grep 追踪开关/变量赋值链（`122` 变量操作、`111` 条件分支）。
- **状态证据**：action=`stateSlots` 找承载剧情状态的开关/变量命名；Grep 追踪赋值与读取位置，确认状态节点与路线节点对应。
- **人物逻辑**：性别、阵营、所属、称谓关系从对白（`101/401` 的 `\N[n]` 与称呼）、`320` 改名事件、`111` 条件分支的名称比较、数据库简介综合取证。任何关系（亲属、敌对、从属）都必须有具体事件或数据库条目佐证，字符重合只用于寻找候选。

## 关系图与实体记录

对象记录、Mermaid 实体关系图与实体方案共用同一份事实依据，随身份、关系变化同步更新：

- 节点表示已确认实体，标签使用工程内现行名称；已确认但没有关系的实体使用孤立节点。
- 连线表示工程证据支持的关系与方向（亲属、所属、敌对、别名、同一命名体系）；未确认关系加入待查记录，不画线。
- 关系可信判据：范围内已确认实体与关系均入图；检查重复节点、错误连接、关系冲突、孤立对象是否遗漏关联线索。

## 成果持久化

调查完成后将成果写入工程记忆（`RmmvMemory`），这是跨会话复用的正式落点：

- 每个重要角色一条 topic（type=`character`）：身份、别名、所属、人物逻辑要点、关键登场位置（地图/事件 ID 索引，不复制原文）。
- 实体关系图与命名体系存一条 topic（type=`convention`），Mermaid 源码直接入 body。
- 术语与消歧规则存一条 topic（type=`decision`），记录采用的词形、适用条件与证据位置。
- 种子账本、中间取证 JSON 只留在 `AGENT_RPG_TMP_DIR`，不写入记忆。

## 成果验收

- **调查完整**：实际范围与证据相符，全部发现对象均有结论，未决对象有具体补证问题。
- **关系可信**：实体与关系均有工程证据，无凭字符重合判定的事实。
- **记忆一致**：记忆条目、关系图与实体记录一致，节点和连线可追溯到证据位置。

调查范围尚未覆盖、验收发现遗漏时，补充或更新种子，继续循环。

## 交付

首先在回复中展示 Mermaid 实体关系图（最多 3 张，每张 ≤10 实体，按家族/组织/命名体系拆图）。然后说明：

- 实际调查范围与覆盖程度，区分程序扫描、实际阅读和实体判断。
- 主要发现、收录与取舍依据；没有发现术语时说明调查依据。
- 已确认实体、身份未明候选各自的数量；未决事项与继续条件。
- 已写入的记忆条目列表（relPath + 摘要）。
