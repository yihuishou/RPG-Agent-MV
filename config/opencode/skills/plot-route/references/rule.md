# 实体与术语规则判据

术语与实体记录保存普通语境阅读难以稳定推出的专有身份、指代、消歧和作品特有事实。本工程中术语的用途是**保证剧情修改与内容制作的一致性**：改对白、改事件、改数据库时，同一实体的名称、称谓、设定事实必须保持一致。先判断对象是否需要收录，再核验规则能否安全表达。

## 收录与身份

- 人名、别名、姓氏、地名、家族、组织和作品特有的物品、技能、生物、概念，在身份能够合理建立且需要保持一致时应当收录。
- 普通职业、称谓和描述性表达，只有承担必要身份、消歧或特殊写法时才需要收录。出现频率、重复次数不能单独证明资格。
- 判断依据依次采用：用户明确指定、工程语境、已核验同类对象、一般语言知识。工程反例优先于一般经验。

## 实体、名称与关系

- 实体是名称指向的对象。同一实体可以有多个名称形式；同一名称也可能指向不同实体，须依据语境消歧。
- 实体身份、名称形式和覆盖范围分别判断，记录数量不代表实体数量。
- 同一实体、别名、包含、所属和同一命名体系表达不同事实。每个身份与关系判断关联到工程证据（文件、地图 ID、事件 ID、数据库条目 ID）。字符重合与 Grep 分组只用于寻找候选。
- 未确认关系保留具体补证问题，孤立对象可以成立。人物与其创立的组织分别记录为实体。
- 判断能否共用一条规则时，还需核验所属关系、命名体系和具体用法。一条词根规则可以覆盖多个名称形式或相关实体，必要的身份区别仍须保留。

RMMV 名称依赖位置（改写或统一名称时必须协调，缺一处会改变游戏行为）：

|主题|依赖位置|
|---|---|
|角色名|数据库初始名、`320` 改名事件、`111` 条件分支的名称比较、脚本 `setName` / `name =` 赋值、`303` 名称输入。允许玩家改名的角色在对白中只能用 `\N[n]`|
|同一角色多阶段名字|每个名字分别对应自己的依赖位置，合并前逐处取证|
|分类名|`equipTypes`、`skillTypes`、`elements` 等可能被插件、`note` 或脚本按名称引用（如 `<属性威力:陰>`）|
|脚本文本|MV/MZ 优先查 `TextManager`、`$gameMessage.add`、`addCommand`、`setText`；模块名或字符串形状不能单独证明用途|
|开关/变量|`System.json` 命名只是辅助；真实语义由赋值（`122` 等）与读取（`111` 等）位置决定|

## 字段与应用

|字段|形成依据|
|---|---|
|词形（词根）|原文中精确连续字面量。选择最短且自然稳定的边界，Grep 按字面匹配|
|标准写法|工程内该实体应统一使用的名称或译法；与数据库现行值一致，除非用户明确要求修改|
|条件与消歧（info）|影响指代与用法的必要事实。角色的 info 写明"男性角色""女性角色"或"未知性别角色"，按需补充职业、阵营、所属、与其他实体的关系|
|证据位置|文件 + 地图 ID + 事件 ID 或数据库表 + 条目 ID；无证据的判断不得入档|

- 同一字面量存在其它义项或命中普通词内部片段时，先检查局部语境能否可靠区分。可以区分时，在 info 中说明采用本条的条件及其它用法的处理原则。条件不足时，调整词形边界或拆分实体、别名与固定分支。
- 修改实体记录前，核对目标对象身份、字段含义和适用条件；覆盖变化时重新核验收敛后的证据。

## 选择词根与精简规则

取舍顺序：资格、写法正确性、覆盖充分性、边界安全、作品风格、一致性，最后才是集合最小性。词根取满足语义与安全条件的最短自然稳定边界。

### 建立对象与候选

- 先确认各对象的身份、标准写法和必要区别，保存对象到规则的覆盖对应。
- 对已确认属于同一对象或体系的多个词形，枚举公共连续片段（≥2 字素、覆盖每个成员词形至少一半）作为词根候选，从短到长逐项确认：成员具有共同身份；标准写法适用于各分支；剩余文本能按语境正常组合；词根保留必要的身份区别与消歧信息。

### 核验完整命中

- 采用候选前，用 Grep 取得它与精确分支的完整出现位置证据，逐项核验新增命中（包括同一事件中原命中旁新增的片段）。数量相同不能证明覆盖、身份或写法相同。
- 将命中分类：目标用法（确认共同身份）、其它义项（依据局部语境形成条件）、新对象（各自补证并检查对已有方案的影响）。
- 在满足上述条件的候选中选择最短自然稳定边界。没有安全合并方案时保留精确分支，并记录身份或边界依据。

判断示例：

|事实|处置|
|---|---|
|`セラ`、`セラ王女`、`セラ殿` 指同一角色，称谓可正常组合|可用 `セラ` 覆盖，核验词根新增命中|
|`セラ教団` 与角色 `セラ` 无关|分别保留身份，避免仅凭字符重合合并|
|`黒騎士`、`白騎士` 的区别来自前缀|保留区别，普通词 `騎士` 无法承担两个固定概念|
|角色名也表示普通"月亮"，句内能辨认|用条件说明保留角色写法，其它义项按语境处理|
|公共词根新增大量普通词命中且局部语境无法区分|保留安全精确分支，对象的收录资格仍然成立|

### 验收最终集合

- **对象覆盖**：每个应收录对象由安全的直接、条件或精确分支规则覆盖，合并与拆分后的成员去向可追溯。无法安全表达的对象保留具体未决与继续条件。
- **命中安全**：每条规则的全部命中均已分类；目标用法采用标准写法，其它用法有可由局部语境判断的处理条件，无法区分的命中已经收窄或拆分。
- 删减前确认保留规则能承担拟删除规则的对象身份、标准写法和适用条件；合并、删除或调整后重新计算覆盖并核对命中适用性，出现缺口时恢复安全分支。

范围外保留规则作为最终集合事实参与检查。未决对象仍是尚未完成的覆盖目标，交付按实际范围说明。
