# 4.5 技能配置

本文总结 Skill 在开发版与正式发布版（Luna RPG Agent）中的配置位置与配置方式。Skill 的定义与工作机制见 [4.2 技能](4.2-skill.md)。

## Skill 目录结构

一个 Skill 是一个目录，放在某个技能区下：

```text
my-plugin-events/
├─ SKILL.md          # 必需：frontmatter + 正文
├─ scripts/          # 可选资源
└─ references/
```

`SKILL.md` 必须包含 frontmatter：

```markdown
---
name: my-plugin-events
description: 当任务涉及 XX 插件的事件指令、需要按该插件改造事件系统时使用
---
```

- 目录名与 `name` 使用小写连字符（如 `event-pacing`）；经设置界面创建时名称还受 `^[a-z0-9][a-z0-9-]*$` 约束。
- `description` 是唯一的触发依据：模型平时只看到名称与描述，任务匹配描述时才会读取正文。描述必须写清插件名与适用场景。

## 技能区一览

| 技能区 | 作用域 | 生效原理 | 开发版路径 | 发布版路径 |
|---|---|---|---|---|
| 出厂区 | 所有工程 | 静态配置 `skills.paths` 指向该目录 | `RPG-Agent-MV\config\opencode\skills\` | `<安装目录>\resources\app\config\opencode\skills\` |
| 用户区 | 所有工程 | opencode 启动时扫描配置目录下的 `skills\` | `RPG-Agent-MV\.opencode\skills\` | `%APPDATA%\Luna RPG Agent\.opencode\skills\` |
| 工程区 | 单个游戏工程 | opencode 从当前工程目录向上发现 | `<游戏工程>\.agents\skills\`（或 `.claude\`、`.opencode\`） | 同左 |
| 草稿区 | 不生效 | 不被任何扫描覆盖 | `<根>\.opencode\logs\skills\` | 同左（位于用户数据根） |

- 草稿区即 `AGENT_RPG_SKILL_OUTPUT_DIR`。按运行时规则，Agent 只能把 skill 草稿写到这里，由你确认后手动移入正式区。
- 此外 opencode 还会扫描用户主目录下的 `.agents\skills\` 与 `.claude\skills\`（产品未禁用）。
- 发布版有两个根：安装根 `<安装目录>\resources\app`（只读、随包更新）与用户数据根 `%APPDATA%\Luna RPG Agent`（可写、升级保留）；开发版两者都是产品根目录。

## 三种配置方式

### 方式一：设置界面创建（发布版推荐）

1. 打开 设置 → 规则与技能。
2. 在「+ 新建 Skill」表单填写名称与描述。
3. Skill 骨架会生成到用户区（发布版为 `%APPDATA%\Luna RPG Agent\.opencode\skills\<名称>\SKILL.md`），点「打开」或直接到该路径补充正文。

说明：

- 该方式免管理员权限，数据随用户目录保留，应用更新不丢。
- 页面列表只显示出厂区 skill（标注「原生」，不可单独开关）；自己新建的 skill 不会出现在列表中，编辑请直接前往用户区路径。

### 方式二：手动放置文件

- 全局生效：放入用户区（推荐）；也可以放入出厂区——发布版出厂区在安装目录内，装在 `Program Files` 时需管理员权限，且**应用更新或重装会覆盖该目录**，不建议长期存放自定义 Skill。
- 单工程生效：放入游戏工程的 `.agents\skills\`，只对该工程的会话可见。

### 方式三：随安装包发布（维护者）

在仓库 `config/opencode/skills/` 下添加 Skill 目录，执行 `npm run release:electron` 打包，Skill 会进入发布产物的出厂区。发布校验（release:check）只强制要求出厂包含 `skill-creator`，不禁止额外 Skill。

## 生效时机

- Skill 扫描在 opencode 引擎启动时一次性完成；新增或修改后请新建会话或重启应用再验证。
- 不要手工修改用户数据根下的 `.opencode\opencode.json` 来追加 `skills.paths`：每次启动产品都会按出厂模板重写该文件。要新增全局 Skill，放入出厂区或用户区目录即可。

## 与其他机制的区别

- 与 [4.4 规则](4.4-rules.md)：Skill 按需触发，承载「怎么做某类事」的专项能力；游戏工程根的 AGENTS.md 是该工程全程生效的长期约束，两者互补。
- 发布版内置 `skill-creator`，可以指导 Agent 按约定结构创建 Skill。正式区只应放成熟 Skill，实验稿留在草稿区。
