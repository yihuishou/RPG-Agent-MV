# 内嵌 OpenCode 运行时升级评估（v1.17.7 → v1.19.6）

> 评估日期：2026-11-18。升级路径与手动流程见根 `AGENTS.md`「内置 opencode 版本与手动更新」。

## 背景

- 产品内嵌 Agent 引擎为 vendored 的 opencode（`third_party/opencode/`），当前版本 **v1.17.7**（tag `v1.17.7`，commit `4ed4f74`）。
- 上游 `https://github.com/anomalyco/opencode` 最新版 **v1.19.6**（2026-11-17 发布），间隔 1787 个 commit。
- 本次评估基于上游两个 tag 之间的完整 diff（约 2600 个变更文件）逐项核对产品集成面。

## 结论

**可以升级。集成面基本兼容，主要工作量在 bun 补丁重做。**

## 集成面核对（低风险）

| 集成面 | 核对结论 |
|---|---|
| Skill 系统 | 本地 `skills.paths` 挂载、`SKILL.md` 格式、skill-as-command 机制均未变化；上游仅内部重构（`escapeHtml`、LayerNode 声明方式）与远程 skill 缓存改进（版本化刷新）。`plot-route` 等 skill 不受影响 |
| Config 注入 | 配置解析更宽松：未识别顶层 key 从抛错改为忽略（`onExcessProperty: "ignore"`），`OPENCODE_CONFIG_CONTENT` 动态注入更安全 |
| SDK 方法面 | `packages/sdk/js/src/v2/gen/sdk.gen.ts` 客户端方法几乎零变化；`createOpencodeClient`（v1 与 v2 入口）签名保持 |
| 事件协议 | 后端对运行时事件按字符串 duck-typing 处理；依赖的 wire 事件名 `session.idle`、`session.status`、`session.error`、`message.part.updated`、`todo.updated`、`permission.asked`、`permission.replied` 上游全部仍在使用，无一删除 |
| Command 系统 | 内部实现调整，skill 自动暴露为 command 的机制不变 |

## 升级步骤（执行记录）

> **执行结果（2026-11-18）**：升级已完成并验证通过。一个重要修正：上游 fork 自行维护 `patches/` 集合，v1.19.6 已自带更新后的补丁（xai 已重打至 3.0.139、google 仍锁 3.0.73、fff-bun/virtua 补丁随依赖移除），**产品侧无需手工重打任何补丁**——上表的"失效补丁"由上游补丁集直接覆盖。

实际执行与验证记录：

1. 替换 `third_party/opencode/` 为 v1.19.6 源码（保留 `RPG_AGENT_VENDOR.json`；上游已移除 `infra/` 与 `sst.config.ts`）。
2. `bun install --frozen-lockfile` 通过（首次 gyp 编译 `tree-sitter-powershell` 报错为瞬时问题，产物 `tree_sitter_powershell_binding.node` 已生成，重跑确认 no changes）。
3. `RPG_AGENT_VENDOR.json`、`THIRD_PARTY_NOTICES.txt` 已更新至 1.19.6（commit `f4e363c`）。
4. 根 `package.json` 依赖升至 `1.19.6`，lockfile 已刷新。
5. `build-opencode-runtime.ts` 的 `OPENCODE_VERSION` 原为硬编码 `1.17.7`（导致二进制版本号错误），已改为从 `RPG_AGENT_VENDOR.json` 的 `sourceTag` 读取，消除版本漂移。
6. 本机 Bun 从 1.4.0 升至 **1.4.4**（上游构建脚本要求 `^1.4.4`）。
7. `npm run build:opencode-runtime` 成功，`opencode.exe --version` 输出 **1.19.6**，冒烟测试通过。
8. 全量验证（`npm run check:local` 的 backend 段 + desktop 全量 + 关键断言单独复跑）：
   - backend 1191 用例 / 54 失败，desktop 726 用例 / 10 失败——经 git worktree 基线（升级前 HEAD）逐文件对比，**失败集与升级前完全一致**（资产复制、试玩运行时、迁移等环境依赖用例），均为本机既有问题，与升级无关；
   - backend typecheck 错误数与升级前持平（16 个既有错误）；
   - opencode 核心 38 用例（runtime/config/catalog）与 release-boundary 20 用例全部通过；
   - 依赖的 wire 事件名与 `--experimental-strip-types` 启动方式断言均正常。

## 回退方案

升级前打 git tag 或记录当前 commit；出现不可修复的补丁冲突或运行时回归时，`git checkout` 恢复 `third_party/opencode/`、根 `package.json` 与 lockfile 即可回退。
